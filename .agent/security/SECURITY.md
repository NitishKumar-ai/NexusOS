# 🛡️ NexusOS — Security Model (AgentShield)

## AgentShield Overview

AgentShield is a published npm security package (NOT a folder to copy):

```bash
pnpm add ecc-agentshield          # Install in packages/agent-harness
npx ecc-agentshield scan          # Quick scan
npx ecc-agentshield scan --fix    # Auto-fix safe issues
npx ecc-agentshield scan --opus   # Deep: 3 Opus 4.6 agents (red/blue/audit)
```

**Stats:** 1282 tests · 102 static analysis rules · 98% coverage · Grade A-F output

## Three-Pillar Defense Model

### Pillar 1 — Command Gating
Blocks dangerous shell commands at the agent harness level before execution:

| Pattern | Action |
|---|---|
| `rm -rf` any path outside repo | BLOCK + LOG |
| `sudo` any command | BLOCK + LOG |
| `curl` with data exfiltration patterns | BLOCK + LOG |
| Credential harvesting patterns | BLOCK + LOG |
| `git push --force` on main/master | BLOCK + NOTIFY |
| Writing to paths outside project root | BLOCK + LOG |

### Pillar 2 — Filesystem Isolation
- Agent sandboxed to the project repo directory only
- Cannot traverse to `../`, `/home/`, `/etc/`, or system paths
- .temp_clones/{task_id}/ is the only allowed working directory
- Read access to repo, write access only to task-specific clone

### Pillar 3 — Zero-Trust Secrets
- Secrets never logged anywhere (Traffic Controller, WebSocket, dashboard)
- Masked in all WebSocket event streams before broadcast
- Injected only at runtime via MCP, never stored in agent context
- Destroyed with session on P8 completion or mission failure
- AgentShield scans 14 secret patterns: sk-, ghp_, AKIA*, etc.

## AgentShield in the P0–P8 Pipeline

AgentShield runs at **P6 (Review)** automatically:

```
P5 Verification (tests pass)
        ↓
P6 Review:
    1. npx ecc-agentshield scan → generate report
    2. Critical findings (grade F/D) → BlockerEvent → mission paused
    3. Non-critical findings (grade C/B) → flagged in P8 approval report
    4. Clean scan (grade A) → auto-advance to P7
```

---

## Security Incident Response

When AgentShield blocks an action:

1. BlockerEvent emitted with `blocker_type: SecurityCritical`
2. Mission paused at current phase
3. Telegram notification: "🔴 Security block — [rule triggered] — [attempted action]"
4. Dashboard shows incident in Security tab with full trace
5. Developer reviews in dashboard → can:
   - **Whitelist** the action for this agent (adds to allowlist)
   - **Reject** the mission entirely
   - **Modify** the task instruction and restart

## Remote Command Security

All Discord/WhatsApp/Telegram commands require authentication:

```
/run [agent] [task]   → requires developer token in command OR pre-configured for channel
/approve [task_id]    → requires developer token
/reject [task_id]     → requires developer token
```

Implementation:
- Each developer has an API token generated by NexusOS on first setup
- Token validated by Traffic Controller before any command is processed
- No anonymous control ever — every command is attributed to a developer
- Commands from unknown sources are silently dropped + logged

## Compliance Summary

| Requirement | Implementation |

| Audit trail | All agent actions logged with timestamp, agent ID, phase, outcome |
